# Upgrade to Import 2.0

This document lists the backward incompatible changes of the Import module 2.0 and what has to be done about them.

The Import module 2.0 requires AtroCore 3.0. The modules extending the Import module - Import Remote File, Import Database, Import HTTP, Synchronization - require the Import module 2.0.

## Import feed types are subtypes

Every import feed type is a subtype of `ImportFeed`: `ImportFeedTypeSimple` of the Import module, `ImportFeedTypeFtp` and `ImportFeedTypePath` of the Import Remote File module, `ImportFeedTypeDatabase` of the Import Database module and `ImportFeedTypeHttp` of the Import HTTP module. The values of `type` are not changed. The subtypes are described in the upgrade notes of AtroCore 3.0.

- **`ImportFeed` keeps everything shared by the types**: the name, the type, the processing type, the entity, the file, the format and the settings of the source and of the processing, the source fields, the configurator, the jobs, the headers of the HTTP request and the relations. The `data` field keeps the other data of the import feed.
- **The settings of the source and of the processing are columns of the import feed**: `entity`, `format`, `fileFieldDelimiter`, `fileTextQualifier`, `headerRowNumber`, `dataStartRowNumber`, `sheetOptions`, `decimalMark`, `thousandSeparator`, `adapter`, `rootNode`, `excludedNodes`, `keptStringNodes`, `delimiter`, `fieldDelimiterForRelation`, `emptyValue`, `nullValue`, `markForNoRelation`, `markForUnlinkedAttribute`, `skipValue`, `skipMissingSourceFields`, `feedPayload`, as well as `script` of the Synchronization module. They were stored in `data.feedFields` before; the upgrade moves them.
- **The settings of a type are fields of its subtype**: `connection`, `dirPath`, `fileMask` and `deleteFileAfterImport` of `ftp`, `dirPath`, `fileMask` and `deleteFileAfterImport` of `path`, `connection`, `query` and `limit` of `database`, `connection`, `httpMethod`, `httpUrl`, `httpBody`, `httpOffset`, `httpLimit`, `httpTotal` and `mergeResponses` of `http`. The upgrade moves them from the columns and from `data.feedFields`. `simple` has no fields of its own. The metadata `import.connection.types` is removed: a type with a connection has the `connection` field in its subtype.
- **The REST API creates an import feed via its type**, e.g. `POST /api/ImportFeedTypeSimple`; `POST /api/ImportFeed` is not available. The routes of the import feed (`runImport`, `generateURL`, `detectSourceFields` and the others) take the ID of the import feed record. The upsert of an import feed is done via its subtype as well; the records of the import feed, e.g. the configurator items and the headers, refer to the import feed record.
- **The `Trello` option of the type is removed.** The Projects module added it without an import type.
- **Creating an import feed from an export feed creates a file import feed** (`ImportFeedTypeSimple`).

## Behavior changes

- **An import feed can be configured for a subtype**, e.g. `AttributeTypeInt`. An import feed of an entity with subtypes imports the fields of the supertype only and creates a record via the subtype named by the `type` value of the row, an import feed of a subtype imports the fields of the supertype and of the subtype.

- **The query of a database import feed fills the source fields.** Trying the query on the record of the import feed stores its columns as the source fields of the import feed.

## Custom code

- **`ImportFeed::getFeedField()`, `getFeedFields()` and `setFeedField()` are removed.** The settings of the source and of the processing are read from the import feed, `$importFeed->get('format')`, the settings of a type from the subtype record, `$importFeed->getSubtype()->get('httpUrl')`, `$importFeed->getSubtype()->get('connectionId')`. This applies to the processing types of `data/custom-code/ImportProcessingTypes` as well.
- **`$importFeed->get('data')->feedFields` is not maintained anymore.** The values of the import feeds created before the upgrade stay in it, they are not read.
- **A module adds an import type as a subtype**: the scope `ImportFeedType<Type>`, its entityDefs, the detail and relationships layouts and the job of the type registered as `ImportType<Type>` in `app.jobTypes`. The subtype gets the views and the panels of `ImportFeed`. A module adding fields to `ImportFeed` for its type has to move them to its subtype; its `ImportFeedLayout` listener for the detail layout is replaced by the layout of the subtype, and its checks of the type belong to the repository of the subtype. A module changing the fields of `ImportFeed` does it in the `loadData` method of its metadata listener, so that the subtypes get the changes.
